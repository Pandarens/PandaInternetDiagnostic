# 🐼 Panda Internet Diagnostic

Программа для Windows, которая постоянно следит за интернетом и при каждом сбое пишет, **где именно и почему** он произошёл: в ПК, в кабеле, в Wi-Fi, в роутере, на линии/оптике или у провайдера.

Работает на любом ПК и с любым роутером: шлюз, модем провайдера, первый узел провайдера и тип роутера определяются автоматически.

## Скачать

**[⬇ PandaInternetDiagnostic.exe](https://github.com/Pandarens/PandaInternetDiagnostic/releases/latest/download/PandaInternetDiagnostic.exe)** — один файл, около 10 МБ, установка не нужна. Windows 10/11.

1. Скачайте файл и запустите его. Windows спросит разрешение на запуск от имени администратора — нажмите «Да».
   Права нужны для проверки сетевой карты, журнала Windows и кнопок «Исправить».
2. Если появится синее окно «Windows защитила ваш компьютер», нажмите «Подробнее» → «Выполнить в любом случае».
   Так Windows реагирует на любую программу без платной цифровой подписи.
3. Откроется окно с кнопкой **«Проверить»**.

Программа обновляется сама: новый код скачивается с GitHub и подхватывается на лету, без переустановки и без перезапуска.
Настройки и история хранятся в `%LOCALAPPDATA%\PandaInternetDiagnostic`. Если положить `config.json` рядом с exe, программа работает в портативном режиме.

## Простая проверка (для всех)

Запустите `start.bat`, откроется страница с одной большой кнопкой **«Проверить»**. Программа по шагам проверит цепочку компьютер → Wi-Fi/кабель → роутер → линия провайдера → интернет → сайты (и при желании скорость). Потом простыми словами покажет:

- **где проблема**: на картинке цепочки сломанное звено подсвечено красным с меткой «Проблема здесь»;
- **что случилось**: одна фраза без терминов;
- **что сделать**: пронумерованные шаги, выполненные можно отмечать нажатием;
- **текст для провайдера**, если проблема на его стороне: готовое сообщение с фактами, его можно скопировать в чат поддержки;
- **скорость** и что она значит («хватит на 4K видео»).

Вверху всегда видно, работает ли интернет прямо сейчас и сколько раз он пропадал за сутки. Графики, журнал, роутер и нагрузка доступны по ссылке «Для специалистов».

## Постоянное наблюдение

Пока программа запущена, она проверяет связь каждую секунду. Внизу главной страницы есть блок «Постоянное наблюдение»:

- **Вкл/выкл** — большой переключатель; выбор запоминается.
- **Запускать вместе с Windows** — программа стартует тихо, без окна. Exe регистрирует задачу в Планировщике с наивысшими правами (без окна UAC при каждом входе); версия из исходников кладёт `PandaInternetDiagnostic.vbs` в автозагрузку. При выключении всё удаляется.
- **Уведомления Windows** — «Интернет пропал: причина…» и «Интернет вернулся, не было 2 мин».
- **Полоса суток или недели** — зелёным время наблюдения, красным обрывы, жёлтым микрообрывы.
- **Журнал обрывов простыми словами** — у каждого обрыва метка «роутер», «провайдер», «Wi-Fi» или «кабель».
- **Выводы по истории** — например, «Роутер регулярно зависает (3 раза)» с советами или «Провайдер отключал интернет 4 раза» со списком времени для звонка в поддержку.

## Неисправный роутер

Программа отдельно распознаёт:

| Ситуация | Как определяется |
|---|---|
| Роутер завис | кабель к роутеру подключён (линк есть), но роутер не отвечает ни на ping, ни на веб-порт |
| Роутер сам перезагружается | после обрыва аптайм роутера оказывается меньше времени с начала обрыва (если доступен API/SNMP/UPnP) |
| Роутер зависал и «отвис» | роутер не отвечал, но аптайм не сбросился |
| Роутер не тянет нагрузку | во время теста скорости пинг до роутера растёт больше чем на 15 мс или появляются потери |
| Bufferbloat | под нагрузкой пинг до провайдера растёт больше чем на 60 мс |
| Сломан DNS внутри роутера | роутер раздаёт себя как DNS и не отвечает, а публичные DNS работают |
| Второй роутер / конфликт IP | у адреса роутера сменился MAC |
| Регулярные зависания | по истории: 2 и больше обрыва из-за роутера за двое суток → советы про блок питания, перегрев, прошивку, замену |
| Перегрев, загрузка CPU, память, ошибки и скорость портов, падения WAN | через API роутера или SNMP |

## Запуск из исходников

Нужен Python 3.10+ (только стандартная библиотека).

| Файл | Что делает |
|---|---|
| `start.bat` | Постоянный мониторинг и окно программы |
| `diag.bat` | Разовая полная диагностика в консоли с тестом скорости, отчёт сохраняется в `data\report_*.html` |

```bash
python launcher.py                    # мониторинг + окно
python launcher.py diag --speed       # разовая диагностика
python launcher.py events --hours 168 # история обрывов за неделю
python launcher.py router-dump        # сырые ответы роутера (для отладки новых прошивок)
python launcher.py init               # создать config.json
```

## Сборка и выпуск версии

```bash
pip install pyinstaller
python build.py
```

В `dist\` появятся:
- `PandaInternetDiagnostic.exe` — один файл без консоли, запрашивает права администратора;
- `panda_diag-<версия>.zip` — код приложения;
- `update.json` — версии и SHA-256 для автообновления.

**Как выпустить новую версию:** поднимите `__version__` в `panda_diag/__init__.py`, допишите `CHANGELOG.md`, закоммитьте и отправьте тег:

```bash
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions прогонит тесты, соберёт exe и опубликует релиз. Установленные программы подхватят его сами.

**Как устроено обновление.** Exe — это стабильный «лаунчер» с Python внутри. Код приложения лежит в zip-архиве:
- новая версия кода скачивается, проверяется по SHA-256 и подгружается **внутри работающего процесса**;
- если код требует более нового лаунчера (`MIN_LAUNCHER` > `LAUNCHER_VERSION`), программа скачивает новый exe, подменяет себя и перезапускается за пару секунд;
- если скачанное обновление не запускается, программа откатывается на предыдущую рабочую версию.

Тест `tests/test_launcher_deps.py` следит, чтобы код не начал использовать модуль стандартной библиотеки, которого нет в exe. Если тест падает, добавьте модуль в импорты `launcher.py` и поднимите `LAUNCHER_VERSION` и `MIN_LAUNCHER`.

Лог программы: `%LOCALAPPDATA%\PandaInternetDiagnostic\app.log`.

## Что проверяется

**Цепочка ПК → роутер → модем/ONT → провайдер → интернет.** В режиме мониторинга каждый узел пингуется раз в секунду. Когда интернет пропадает, программа фиксирует, какие узлы ещё отвечают, и сразу запускает глубокую диагностику. Так причина сохраняется именно на момент сбоя.

- **ПК:** кабель отключён, линк согласовался на 100 Мбит/с вместо гигабита (2 пары, плохой обжим, порт), полудуплекс, ошибки сетевой карты, энергосбережение EEE, DHCP не выдал адрес, исчерпание TCP-портов Windows.
- **Wi-Fi:** сигнал (дБм), канальная скорость, роуминг между точками, смена канала (DFS-радар), отключения из журнала WLAN.
- **Роутер:** завис или не отвечает, CPU, память, температура, перезагрузки, скорость и ошибки портов.
- **WAN:** нет линка на WAN-порту (кабель/ONT), PPPoE/DHCP не подключён с кодом ошибки (691 — логин/пароль/долг, 678 — провайдер не отвечает и т.д.), WAN-порт на 100 Мбит/с, CRC-ошибки, падения линка.
- **Оптика (GPON):** уровень RX/TX в дБм, LOS, состояние PON (O5), перегрев модуля — через SFP роутера (MikroTik) или веб-интерфейс ONT Huawei/ZTE.
- **DSL:** SNR, затухание, CRC/FEC (Fritz!Box и TR-064).
- **4G:** RSRP/RSRQ/SINR (модемы Huawei).
- **Провайдер:** «интернет не поступает в роутер», «до провайдера есть связь, дальше нет», потери и задержки по участкам.
- **DNS/HTTP:** основной DNS не отвечает, медленный DNS, подмена ответов (captive portal).
- **Нагрузка:** общий канал, кто из устройств сколько качает, загрузка портов роутера.
- **Wi-Fi эфир:** загруженность каналов 2.4/5 ГГц, рекомендуемый канал, ширина канала, предупреждение о DFS, совет перейти на 5 ГГц.
- **Скорость:** тест загрузки, распознавание «потолка ~94 Мбит/с» (где-то 100-мегабитный участок).

## Поддерживаемые роутеры

Тип определяется автоматически: по MAC-адресу производителя, затем по веб-интерфейсу. Если API производителя недоступно, программа переходит на UPnP и SNMP.

| Роутер | Что нужно |
|---|---|
| **Xiaomi / Redmi** (MiWiFi) | пароль администратора |
| **MikroTik** | пользователь с правами `read`; подключение через REST или API 8728/8729 (скрипт включения — в настройках); без пароля — через SNMP |
| **Keenetic** | логин/пароль администратора |
| **ASUS** (ASUSWRT / Merlin) | логин/пароль; трафик по устройствам — при включённом Traffic Analyzer |
| **OpenWrt / ImmortalWrt** | пароль root, пакет `uhttpd-mod-ubus` |
| **TP-Link** (Archer, Deco, MR/MX…) | пароль + `pip install tplinkrouterc6u` |
| **Fritz!Box** и др. TR-064 | логин/пароль, «Доступ для приложений» включён |
| **Huawei 4G-модемы** (B315/B525/B535/E5186…) | пароль + `pip install huawei-lte-api` |
| **Любой с UPnP** | ничего (только статус WAN) |
| **Любой с SNMP v2c** | community (по умолчанию `public`) |
| **ONT Huawei / ZTE** (оптика) | адрес и пароль ONT в разделе `ont` |

## Доступ к роутеру

Кнопка **«⚙ Роутер и модем»** вверху окна. Программа сама определяет модель роутера и показывает только нужные ей поля
(для Xiaomi — пароль, для MikroTik — логин, пароль и способ подключения и т.д.). Там же подсказка, где взять пароль,
и кнопка **«Проверить подключение»**. Если роутер требует пароль, а его нет, программа не подбирает его вслепую:
она предлагает ввести пароль на главной странице и после проверки, а пока использует то, что доступно без пароля (UPnP/SNMP).

- **MikroTik:** перебираются REST по HTTPS и HTTP, а также API на портах 8728/8729 (сертификат не нужен). В настройках есть готовый скрипт:
  он создаёт пользователя только на чтение и открывает API только для этого компьютера.
- **ONT провайдера** (Huawei/ZTE): адрес, логин и пароль терминала — для уровня оптического сигнала.
- **Тариф:** чтобы программа понимала, когда канал забит полностью.

Пароли хранятся только на этом компьютере в `config.json`, зашифрованными Windows DPAPI (расшифровать может только этот пользователь Windows).

Дополнительные параметры можно задать в `config.json` вручную: `outage_threshold_sec` (порог «обрыв / микрообрыв»),
`anchors` (внешние серверы для проверки), `web_port`.

## Почему нестабильный интернет — как программа делает вывод

Вывод строится не по одной проверке, а по всей истории наблюдения (сутки или неделя):

- **Каждый обрыв** классифицируется по тому, какие узлы отвечали в первые секунды: компьютер, роутер, провайдер, интернет.
  Затем глубокая проверка уточняет причину, пока связи ещё нет.
- **Контекст в момент обрыва:** сигнал и точка Wi-Fi, линк кабеля, загрузка канала, загрузка процессора роутера, время его работы.
  После обрыва программа проверяет, не перезагрузился ли роутер сам.
- **Закономерности:**
  - обрывы вечером — перегрузка у провайдера;
  - ровно раз в сутки — принудительное переподключение PPPoE/DHCP;
  - с постоянным интервалом — роутер перезагружается или не может продлить адрес;
  - при слабом Wi-Fi;
  - при загруженном канале;
  - при перегруженном роутере.
- **Хронические потери:** почасовые потери и пинг по участкам «компьютер ↔ роутер», «до провайдера», «интернет»;
  отдельно — рост пинга вечером относительно ночи.
- **Не считаются обрывами:** сон компьютера и первые секунды после пробуждения. Отдельно учитываются случаи
  «связь есть, но сайты не открываются» (DNS) и «часть интернета недоступна» (маршрутизация у провайдера).

Итог — виновник (роутер, Wi-Fi, кабель, сетевая карта, линия провайдера, сеть провайдера, DNS), уверенность в процентах,
доказательства, что сделать, кнопки исправления и готовый текст для провайдера со временем обрывов.
При одном-двух обрывах программа честно пишет «Возможная причина» и просит понаблюдать дольше.

## Данные

- `data\history.sqlite` — пинги (14 дней), события и снимки диагностики в момент каждого обрыва.
- `data\report_*.html` — отчёты разовой диагностики, их можно отправить провайдеру или мастеру.

## Тесты

```bash
python -m unittest discover tests
```

Кроме сценариев аварий проверяется, что все используемые модули стандартной библиотеки попадут в exe.

20 смоделированных аварий: обрыв оптики, ошибка PPPoE, WAN на 100 Мбит/с, авария у провайдера, DNS, Wi-Fi помехи, детектор обрывов.
